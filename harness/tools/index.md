# Tools

Scripts grouped by the system or concern they serve. Open the folder your task touches. Agents reach cloud, Sonar and a locally
running app only through the read wrappers (CLD.1, SEC.2); the guard hook and the install allow rules name those paths.

* [harness/](harness/) - `bundle.py` selects rules, checks the bundle and private-artifact boundary, validates findings, builds indexes, and prepares feedback worktrees; `density.py` ranks candidates for compressing the bundle's prose, which the evals then accept or reject (playbook: compress-harness-prose); `check-adapter.sh` verifies the rules reached an agent's context
* [verification/](verification/index.md) - scoped requirement registry, independent C# change checks, execution receipts and required-result summaries; semantic review remains separate
* [review/](review/) - `review.sh` runs the AI review for one change; `render.py` shows its findings as a readable summary (playbook: review-and-fix); `eval.py` evaluates the same review flow against examples, with `thresholds.json` as its gate; `eval-queue.py` runs those evals one scenario at a time and checks each off, so a run that stops (quota, login) resumes where it left off
* [testing/](testing/) - `check-scenarios.py` is the T.5 gate: a change that reaches the integration suite needs a scenario or a waiver; `business-testplan.py` builds the business end-to-end test plan workbook from a spec (playbook: write-business-test-plan; `coverage-impact.py` is informational, not a gate: given a diff and Cobertura or lcov reports it says which tests execute the changed code, what nothing covers and which layer covers it (T.1, T.3, T.4) — it sets no threshold, and executed is not asserted); `run_candidate.py` freezes an approved scenario and runs one candidate against it through an external agent adapter, optionally in throwaway containers (`container/`, `adapters/`), and `rescore`s a saved run without rerunning the agent (time budget, trace, diff, separate result dimensions); `freeze_eval.py` snapshots and verifies approved task and grader artifacts for any use-example evaluation, and `backup_eval.py` is the independent grader for the local backup use example (criteria F01-F10, F11-F16 from contract v2)
* [iac/](iac/) - `check-iac.py` is the gate for IAC.2, IAC.3 and IAC.4: a Bicep or HCL file that explicitly sets a network default action to Allow, a TLS minimum below 1.2, or Key Vault protections to false fails the PR
* [cloud/](cloud/) - `cloud-read.sh` is the read-only wrapper for `az`, `terraform`, `kubectl` and `hcloud` (CLD.1)
* [deps/](deps/index.md) - `dep-read.sh` is the read-only wrapper for `dotnet`, `npm` and `pnpm` (outdated, deprecated, vulnerable, audit, SDK and runtime lists; advisory lookups need `--allow-network`); `check-currency.py` is the gate for DEL.2: a target framework, SDK pin, Node engine or framework package two or more releases behind current fails the PR, unless a backlog item is linked
* [greenfield/](greenfield/index.md) - `greenfield-init.sh` starts a new repo or service design-first by writing the design, AGENTS.md, verify.sh and analyzer skeletons (never overwriting); `design-check.py` is the static gate `scripts/verify.sh` runs over them (DEL.4, CODE.8, OBS.3, T.3; playbook: start-greenfield)
* [dev/](dev/index.md) - `dev-read.sh` is the read-only wrapper for a locally running app: HTTP GET/HEAD against localhost, `docker ps/logs/inspect/stats`, a local log file, and what is listening on a port; output is redacted best effort and size-capped, and it never starts, builds or stops the app (SEC.1, SEC.2, CLD.1)
* [spec/](spec/index.md) - `spec-note.py` creates and updates a spec note in the user's Obsidian vault at `<vault>/<customer>/specs/<slug>.md` from `templates/spec.md`, refusing to overwrite without `--force` or to write outside the resolved vault root (playbook: write-spec)
* [scaffold/](scaffold/index.md) - `read-conventions.py` reports what one kind of file looks like in the target repo (name, folder, companions, where it is wired up, the lines its files share), with a citation and a confidence per statement, so a new file follows the repo's own convention; it reports an inconsistency rather than picking a winner, and `AGENTS.md` wins over anything inferred (IAC.6; playbook: scaffold-from-conventions)
* [azure-devops/](azure-devops/) - `ado-post-findings.sh` posts review findings to a pull request; `ado-mine-review-comments.py` mines review threads into an anonymised CSV; `ado-run-failure.sh` is the read-only view of a failed run (failed tasks, errors, log tails) and `ado-run-watch.sh` follows a running one until it ends, one line per change, for the Monitor tool; both share `ado-common.sh` (playbook: diagnose-pipeline-failure)
* [servicenow/](servicenow/index.md) - `sn-get.sh` is the read-only wrapper for the ServiceNow Table API (allowlisted configuration tables, credentials off the command line); `sn-access-check.sh` shows which tables the account can read; see its routing table in `servicenow/index.md` (playbook: analyse-servicenow)
* [frontend/](frontend/index.md) - `screenshot.mjs` screenshots a running page at phone, tablet and desktop widths and runs the responsive and WCAG checks, for the AI to look at; `compare-ui.mjs` compares two of its runs and reports what is fixed, new, reduced and increased per viewport, exiting 2 when a round of fixes introduced a new finding or raised an existing count (rules UI.1, UI.2; playbook: verify-frontend)
* [diagrams/](diagrams/) - `dk` builds a one-page draw.io diagram (plus SVG and PNG preview) from a JSON spec, with logos, real draw.io icons, numbered legend and a name tile when a logo is missing; `dk logo` looks up and downloads a software logo, `dk icons` finds icon paths (playbook: draw-integration-diagram)
* [orchestration/](orchestration/) - `orchestrate.py` decomposes complex workloads into subagent work packages and classifies model tiers (`economy`, `builder`, `reasoner`) to optimize token spend (playbook: orchestrate-workload)
* [sonar/](sonar/) - `sonar-read.sh` is the read-only wrapper for the Sonar API, keeping the token off the command line (SEC.2)

New script: put it in the folder of the system it talks to; create a folder when a new system appears, and add a line here.

* [code/](code/index.md) - Roslyn CODE.5 structural check with audit and baseline comparison modes and JSON evidence; `openapi-drift.py` is the gate for DEL.5: a committed OpenAPI snapshot that differs from the document the build generates fails the PR, listing the operations added and removed.

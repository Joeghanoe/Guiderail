# Compare consequential designs

Use when a boundary, dependency, technology or compatibility choice has meaningful alternatives. Inputs are approved outcomes, current contracts and constraints. For routine reversible choices, use the established convention without manufacturing a design exercise.

Compare the current approach and credible alternatives against the same criteria: requirement fit, failure behavior, dependency direction, testability, migration and operating cost. Include the smallest viable change. Sketch the public interface or data flow when it exposes a trade-off that prose hides. Extra model sessions are optional and require authorized delegation.

State what each option optimizes and sacrifices. Check assumptions against the affected code and existing decisions; distinguish measured facts from estimates. Do not reject mandatory I/O seams because there is only one production adapter.

Output the preferred option, rejected alternatives, reasons, compatibility implications and unanswered questions. Use the existing architecture decision process for consequential decisions. Pass the chosen interfaces, constraints and criterion identifiers to planning or implementation. If an unresolved decision blocks the change, name its owner and pause only dependent work.
